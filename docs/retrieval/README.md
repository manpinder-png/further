# Local retrieval

The sidecar runs on `127.0.0.1:8767`, on CPU with two PyTorch threads. Only the server can call `/embed` using the locally generated token. Browser-origin requests are rejected. `GET /health` reports readiness, model revision and dimensions without exposing secrets.

`.gitattributes` keeps `reference-mean.json` in LF format on Windows as well as Unix. Its checksum covers exact bytes; do not change the pinned hash or reference values to accommodate Git newline conversion.

Model: `FacebookAI/roberta-base`, revision `e2da8e2f811d1448a5b465c236feacd80ffbac7b`, 768 dimensions. The current embedding space includes `mean-mask-l2-refmean-l2-v2` plus the full SHA-256 of `reference-mean.json`: attention-mask mean pooling of the final hidden state, L2 normalization, subtraction of a fixed independent reference mean, then L2 normalization again. The checked-in reference contains 40 neutral synthetic English passages and their frozen 768-number mean. Its model revision and exact bytes are checked at startup. No private user data contributes to that mean, and it never adapts during requests. This removes a common direction shared by most raw vectors; it is deterministic postprocessing rather than model training. The unused pooler is disabled. Input is capped at 512 tokens and batches at 16 texts. This is a Meta general language encoder, not a trained sentence retriever.

The model card identifies an MIT license. Contriever was evaluated as a possible retriever, but the official repository's CC BY-NC 4.0 license makes it a poor default for a continuing startup. This is an engineering selection, not a legal determination for every future use. Recheck licenses before distributing model weights.

Current indexes: owner-scoped concept descriptions, explicit current intent and the latest inferred learning interpretation. Only selected intent/goals/concept-title/learning-description fields enter the metadata projection; identity/demographic/profile fields are excluded, common email/number patterns are removed, and source provenance remains in the original metadata record. This projection stays private and never becomes a peer target. Older proposals remain in history while their superseded derived metadata vectors are removed. Resource chunks need a future authorized ingestion adapter. PostgreSQL remains the source of truth. Vectors are replaceable derived data with actor, entity type/ID, content hash, model, revision, dimension and timestamp. Search requires exact model/revision equality and owner scope.

`POST /api/local/search` with `{ "query": "..." }` retrieves the current learner's indexed text. `POST /api/local/reindex` reconciles their saved concepts/intent into durable jobs and starts a background worker; it returns queue counts immediately. `GET /api/local/indexing` returns owner-only counts and resumes recoverable work. Map persistence succeeds independently of indexing. No raw profile, identity, consent, media bytes or hidden reasoning is indexed.

Owner-search queries of at most 200 characters and 12 whitespace-separated words reuse bounded saved learning context when they exactly match an owned concept title/slug or the original question of a successful live map expansion (case and whitespace normalized). Question lookup examines the latest 50 owner runs; descriptions come from up to three still-owned canonical concepts in the latest matching map, capped at 1000 characters. Unrelated questions, fixture/failed runs and removed concepts add no context. Global profile intent, private metadata and peer records are not appended. The original query remains present; this adds no provider call or query persistence. Long queries remain unchanged. This also improves concept recall for the learner's assistant and typed peer-guide queries; peer targets and eligibility remain unchanged. The encoder, stored-vector revision and indexing text are unchanged, so no re-index is required. Broader paraphrase/abbreviation handling and retrieval-trained model selection still require evaluation; this deliberately does not invent a rewrite for an unseen question.

## Durable incremental ingestion

Migration 003 adds `retrieval_index_jobs`. `addConcepts` queues canonical title + hook text in the same transaction as membership/seed events. A changed `currentIntent` queues its replacement inside the profile transaction. Saving an `intent-proposal` queues its bounded private learning projection in that same metadata transaction. Clearing intent removes its queued and indexed representations. One row per owner/entity/model/revision stores current text/hash, generation, attempts, state, due time and lease. Identical source content does not trigger another embedding. Reconciliation repairs pre-migration data and creates work for a newly selected space.

Workers claim at most 16 jobs, batch local inference, and publish vectors plus ready status atomically. An edit invalidates the old lease; expired leases can be reclaimed after restart. Stale worker results cannot overwrite the latest source. Failed batches stay in `retry` with bounded exponential delay and a safe generic error. The per-process worker pumps bounded passes and schedules retries; no processing occurs while every local server is stopped. Reading indexing status or bootstrapping the app can resume persisted work. It is not an independent daemon or distributed worker service.

`enqueueIndexText`, `reconcileIndex`, `processIndexJobs` and `drainBackground` are server-side adapters. Status responses contain counts, never the source text. The current authorized ingestion adapters support concepts, current intent and the latest intent-proposal metadata; resource ingestion needs its own ownership-aware adapter.

## Consented vector discovery

`searchPeerVectors` performs exact PostgreSQL cosine search between the owner's selected concept vectors and eligible peers' active concept vectors. Different canonical IDs can match. Candidate eligibility comes from the repository's existing adult confirmation, opt-in, presence, language, time, block, decline and reservation rules. It exposes only peer ID, paired concept IDs/titles and similarity. Private peer intent, background, metadata and media are excluded. Source hashes and exact model/revision must match current saved content; pending/stale representations are not presented as ready. An invitation still rechecks authoritative eligibility transactionally.

Canonical IDs and source evidence stay unchanged. Cosine similarity is an uncalibrated ordering feature, not a percentage match, expertise score or permission decision.

A November 1 smoke check compared GPU/matrix, SQL/database and yeast/bread queries against related and unrelated passages: all 3 intended passages ranked above distractors. Batch inference took approximately 0.52 seconds on this Mac. Scores were highly concentrated (positive cosines ~0.976–0.983; strongest distractors ~0.953–0.971). This tiny check does not establish production retrieval quality. Do not use an arbitrary cosine threshold to merge concepts, authorize matching, infer mastery or identify people.

A November 2 synthetic smoke set now lives in `domains/retrieval/evaluation.json`; run `python3 domains/retrieval/evaluate.py` against the actual sidecar. Eight differently worded queries against eight passages yielded recall@1 of 7/8 and recall@3 of 8/8. The query about splitting matrix calculations ranked SQL hierarchy just above GPU computation (cosines about 0.96958 and 0.96933). This failure and the narrow margins are evidence against treating raw scores as confidence. The set is small and hand-written; these are smoke results, not production peer-matching accuracy.

Next useful evaluation: a labelled collection of real project concepts, synonyms, ambiguous queries, out-of-domain questions and hard negatives; measure recall@k and wrong-neighbour rate before tuning thresholds or choosing a suitably licensed Meta encoder. Native pgvector ANN indexes remain future work. The base model and attention-mask pooling remain unchanged. Reference-mean centering was selected using a separate exploratory set, then evaluated against the eight-query set above (top-1 improved from 7/8 to 8/8) and a newly written ten-query holdout with related distractor pairs (8/10 to 10/10). All results stayed within top three. These tiny synthetic sets do not establish production quality or a universal acceptance threshold. The current cosine range is different from the raw baseline; never reuse old thresholds. Run `python3 domains/retrieval/evaluate.py --dataset domains/retrieval/evaluation-holdout.json` against the current sidecar to reproduce the second set. The optional `--center-reference` flag is for probing a raw-space sidecar only and refuses double centering.

Old raw-space vectors remain distinguishable by revision and cannot be compared with the new centered space. Reconciliation creates current-space jobs; the live embedding sidecar must restart after a space change. Contriever's official noncommercial license was rechecked before retaining the current base model. Mean subtraction is informed by [All-but-the-Top](https://arxiv.org/abs/1702.01417); this project uses only a frozen mean and does not implement that paper's principal-component-removal procedure.

Sources: [model card](https://huggingface.co/FacebookAI/roberta-base), [Contriever license](https://github.com/facebookresearch/contriever/blob/main/LICENSE), [PGlite extensions](https://pglite.dev/extensions/). Dependencies are pinned in `requirements.lock` and the model revision is checked in the embedding script.

A separate 12-query challenge set improved from 8/12 to 10/12 top-one retrieval after the same fixed-mean transform. Osmosis and reliable-network-delivery paraphrases still selected unrelated first results. The combined smoke evidence is useful for choosing this local baseline, but does not establish production relevance, multilingual quality or a universally safe cosine threshold. The public operating point and relative-pair band remain explicitly experimental.
